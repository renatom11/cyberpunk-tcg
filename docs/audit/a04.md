**Headline:** all four cards bury their second sentence ("... draw 1") inside the continuation of
the first sentence, so when the first sentence does nothing — the player declines the "up to N" /
the "may", or no legal adjustment exists — the independent, state-based draw clause is silently
skipped.

The four findings share one root cause: `EffectCtx.adjust_up_to` and `EffectCtx.choose` take no
`otherwise` in these scripts, and both return without running `cont` on the decline / empty-candidate
path (`src/cptcg/core/effects.py:151-156` for `choose`, `:369-383` for `adjust_up_to`). They are
reported per card because each card's second sentence is a different printed clause.

Suite state after the audit: `788 passed, 10 xfailed` — green.

## Unproven

* **N-NOTE — peace-offering offers sources that cannot legally be copied.** `wnc.py:370` builds
  `others` from every other Gig with no filter, so the menu includes sources whose value is off the
  target die's face (copying a d10's 9 onto a d6) or equal to the target's current value. Ruling 037
  is explicit that such an effect **fails — no change** (and `ops.set_gig:502-506` implements that),
  so choosing one is legal-but-inert rather than wrong. This is a search-branching / UI nicety, not
  a text discrepancy: the printed text does not restrict which other Gig you may name. Recorded as
  a note only — no test, and it should **not** be "fixed" by narrowing the choice without a ruling.
* **S-SUSPICION — "a Gig" reaching the rival's Gig area.** All three adjust cards pass
  `[c.player, c.rival]` as the owners while their payoff clause is friendly-only, which looked like
  a friendly/rival scope error. I wrote the scenario for `trust-no-one` (rival holds the only Gig, a
  d6 at 4; the player decreases it by 1 and draws nothing because *they* control no min Gig) and ran
  it in the scratchpad: it **passed** — `s.gig[1] == [(6, 3)]`, hand empty. The printed text says "a
  Gig" unqualified, `docs/rules.md` gives no default owner, and the set's own convention is to write
  "friendly" when it means friendly (`wnc.py:1370` "Decrease a friendly Gig"). The scripts are
  right, so the test was discarded rather than frozen into `tests/cards/audit/test_a04.py`.

## Clean

No card in this batch is fully clean — each carries exactly one finding, all of it in the final
"draw 1" sentence. Everything else checked clause by clause and found correct:

* **afterparty-at-lizzies** — target scope (any Gig), ±1 amount generation, 0 offered as a legal
  amount, "2 or more Gigs with different values" read as ≥2 distinct values over *your* Gigs, draw
  of exactly 1 by you, condition evaluated *after* the adjust. Only the gating of the draw is wrong.
* **industrial-assembly** — target scope, +1..+4 with the die's max face respected per ruling 037,
  "Gig with 8+ value" counted over your own Gigs only, draw of exactly 1.
* **trust-no-one** — target scope, −1..−3 floored at face 1 per ruling 037, "min Gig" = a die
  showing 1 in your own Gig area, draw of exactly 1.
* **peace-offering** — the "may" is genuinely optional, target and source are any Gig / any *other*
  Gig on either side, the copy writes the source's value onto the target through `set_gig` (so
  ruling 037's failure cases are honoured), "value-pair" counted over your own Gigs with each die in
  at most one pair, draw of exactly 1.
