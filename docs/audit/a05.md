| 6 | `higher than` (strict `>`) | `steps.py:270` `value > pw`. Verified: value **equal** to the thief's power is still stealable. Correct. |

**Rulings checked.** 009 (empty Gig area — n/a, the area is non-empty), 011/012 (BLOCKER redirect —
not touched; the attack is declared on the Gig area), 015 (GO SOLO Legend is a Unit — clears clause
4), 026 (field size — n/a), 029 (power floors at 0 — n/a at power 9), 039 ("until your next turn"
removal timing — clears clause 2). No ruling licenses a steal that ignores a "can't steal"
prohibition, and `docs/rules.md:140-141` defines Steal as one action ("Choose a rival Gig die and
move it to your Gig area"), which is exactly what Gorilla Arms performs.

**Why this is Chrome Fang's finding, not only Gorilla Arms'.** The deviation could be fixed either
in `wnc.py:1031` (filter through `stealable`) or in `steps.py` (move the check into
`StealOneStep`). Either way, the card whose *printed text* is not honoured is Chrome Fang: its
clause 5 is enforced on one code path out of two.

## Unproven

**S-SUSPICION — Gilded Matón / Heywood Ripperdoc: a replaced Gear defeat still pays out.**
Both scripts call `c.defeat(g)` and ignore its return value (`ops.defeat` returns `False` when a
replacement effect takes over, `ops.py` `defeat`). Gilded Matón's text conditions the rival-Unit
defeat on "**If you do**", so a Gear whose defeat is replaced should not pay out. I wrote the
scenario and could not make it fail: the only two `would_defeat` replacements in the pool are
`deadman-transmitter` (`wnc.py:1106-1111`, fires only when the *host* is defeated, never the Gear
itself) and `jackie-welles-mamas-favorite` (`wnc.py:1339-1359`, returns `False` unless
`c.d(inst).type is UNIT`). No card in MS01-WNC can replace the defeat of a Gear, so the branch is
unreachable today. Recording it as a latent fragility, not a finding.
