### AUD-viktor-vektor-drop-your-illusions-1 — B4 (scope: "your first each turn" vs "the first while I am in play")

**Card:** `viktor-vektor-drop-your-illusions` (Unit, 5 €$, 5 power)
**Printed text:** `Play your first CYBERWARE Gear each turn for -3 €$, to a minimum of 1 €$.`
**Script:** wnc.py 816-826.

#### Leg B — clause map

| # | Clause | Implementation | Verdict |
|---|---|---|---|
| 1 | "Play ... for -3 €$" (a cost modifier on another card) | `cost_mod` returning `-3` (wnc.py 818-822) | ok |
| 2 | "your" — only the controller's plays | `p == c.player` (820) | ok |
| 3 | "CYBERWARE Gear" — type and tag | `d.type is GEAR and "CYBERWARE" in d.tags` (820) | ok |
| 4 | "to a minimum of 1 €$" | not in the script; `ops.play_cost` (355-358) clamps a negative delta to `max(1, total)` when `base >= 1` | ok |
| 5 | **"your first ... each turn"** — the discount is spent by the first CYBERWARE Gear the controller plays this turn | `(c.inst, "cyberware") not in c.s.used` (820); the key is written only by `ev` (823-825), an `on_event("played")` hook, and `on_event` runs only for **active** cards (`ops._rebuild_active` slot 4: Units and Gear in play, face-up Legends). The engine already offers the backward-looking query this clause needs: `EffectCtx.played_this_turn`
(`core/effects.py` 139-141) over `s.played`, which `engine.play_card` appends to for every card
type. `s.used` is cleared at the turn boundary (`steps.EndTurnCleanupStep`), so the per-turn scope
itself is right; only the counting window is wrong.

Reachability: ordinary play — equip a cheap CYBERWARE Gear (Mantis Blades, 1 €$) to a Unit already
on the field, then play Viktor, then play Gorilla Arms. The *second* CYBERWARE Gear of the turn is
billed 1 €$ instead of its printed 4 €$.

**Rulings checked:** 019 (once-per-turn scope — *Uncertain*; it fixes when counters **reset** —
both players' counters reset at the start of every turn — and the script matches that default, so
019 does not license the narrower window), 031 (face-down Legends inactive — Viktor is a Unit),
036 (effect-Sell). None applies. `docs/rules.md` "Main Phase / Play" is silent, so the card text
governs.

**Competing reading, for honesty:** "your first CYBERWARE Gear each turn" could be read as "the
first one I see while I am in play". That reading adds a condition the card does not print, and it
is not how the same file reads other backward-looking text (wnc.py 786 uses `played_this_turn`).
I file the finding under the plain reading.

### AUD-saburo-arasaka-stubborn-patriarch-1 — B4 (scope: "Units" excludes a Legend played as a Unit)

**Card:** `saburo-arasaka-stubborn-patriarch` (Legend, no cost, 0 power)
**Printed text:** `Friendly ARASAKA Units have +1 power while attacking. (Units steal an extra Gig for every 10 power.)`
**Script:** wnc.py 848-851.

#### Leg B — clause map

| # | Clause | Implementation | Verdict |
|---|---|---|---|
| 1 | "+1 power" | `power_mod` returning `1` (wnc.py 850) | ok |
| 2 | "while attacking" | `sit & ATTACKING` (850) | ok |
| 3 | "Friendly" | `c.s.i_owner[unit] == c.player` (850) | ok (probed: a rival ARASAKA Minotaur stays at 9) |
| 4 | "ARASAKA" | `"ARASAKA" in c.d(unit).tags` (851) | ok |
| 5 | **"Units"** | `c.d(unit).type is UNIT` (851) — the *printed card type*, so an ARASAKA **Legend** on the field via GO SOLO never gets the +1 | **narrower than printed** |
| 6 | reminder "(Units steal an extra Gig for every 10 power.)" | engine-wide (`steps.steal_count`) | ok, no script needed |
| 7 | a face-down Saburo contributes nothing | `_rebuild_active` lists only face-up Legends; probed (aura absent while face-down) | ok, ruling 031 |

Why clause 5 deviates: `docs/rules.md` prints GO SOLO as *"Pay this Legend's cost to **play it as a
ready Unit**"*, and ruling 015's own default row reads **"Not spendable (it is a Unit now)"**;
ruling 032 quotes the same keyword line to justify firing PLAY on GO SOLO. The engine agrees
everywhere else: `state.units()` (201-205) returns gone-solo Legends, so Adam Smasher's "Defeat a
rival Unit" can hit them, and **Saul Bright's aura ten lines earlier in the same file** (wnc.py
838-840), which tests zone and owner but not card type, *does* give a gone-solo Legend its +2.
Probed directly: with Saul out, a gone-solo Goro Takemura attacks at 9 (7+2); with Saburo out, the
same Goro attacks at 7.

ARASAKA Legends with GO SOLO in the pool: `adam-smasher-ender-of-legends` (9/9) and
`goro-takemura-hands-unclean` (5/7) — a live interaction in any ARASAKA deck.

**Rulings checked:** 015 (GO SOLO spendability / slot — *Uncertain*; the deviation shown is from the
ruling's **own default wording** "it is a Unit now", not from the slot-vacation part the trap list
protects), 027 (a spent Legend may GO SOLO and arrives Lagged — irrelevant to power), 031 (face-down
Legends inactive — implemented), 032 (PLAY fires on GO SOLO; quotes "play it as a ready Unit"),
033/034 (which Legends may be played; removal on leaving — untouched by this clause).

**Competing reading:** a gone-solo card keeps card type Legend, and the engine relies on exactly
that for Meredith's "+2 while fighting a Legend" (`VS_LEGEND` in `steps.fight`). Both can hold at
once — Legend by type, Unit by role — which is how `state.units()` already treats it. Under the
alternative ("Units" = printed type Unit), it is `s.units()`, Saul's aura and Adam Smasher's PLAY
that would all have to change. Either way the engine is internally inconsistent today, and the
printed GO SOLO text points at this script being the odd one out.

### AUD-royce-psycho-on-the-edge-1 — B4 (a condition the text never states: `zone is FIELD`)

**Card:** `royce-psycho-on-the-edge` (Legend, 6 €$, 6+ power, GO SOLO)
**Printed text:** `GO SOLO` / `During your turn, this Legend has +2 power for each of its equipped Gear.`
**Script:** wnc.py 869-872.

#### Leg B — clause map

| # | Clause | Implementation | Verdict |
|---|---|---|---|
| 1 | `GO SOLO` | keyword in `data/cards/wnc.json` | ok, no script needed |
| 2 | "this Legend" | `unit == c.inst` (wnc.py 871) | ok |
| 3 | "During your turn" | `c.is_active_turn()` (871) — probed: bonus gone on the rival's turn | ok |
| 4 | "+2 power for each of its equipped Gear" | `2 * len(c.gear())` (871); `EffectCtx.gear()` -> `state.gear_on`, which resolves Gear in FIELD **or** LEGENDS | ok |
| 5 | *(no such clause printed)* | `and c.s.i_zone[c.inst] is Zone.FIELD` (872) — the bonus is suppressed while Royce sits face-up in the Legends area | **extra condition** |

That board is legal and reachable: `core/legal.py::gear_hosts` (18-20) — *"Legal Gear hosts:
friendly Units on the field, and face-up Legends in the Legends area"* — plus `docs/rules.md`
("Gear — pay its cost and equip it to a friendly Unit or Legend") and nine cards whose reminder
text reads "(Equip to a friendly Unit or face-up Legend.)". A face-up Royce holding two Gear in the
Legends area is 6 + 4 (printed Gear power) + 4 during your turn by the text; the engine says 10.

**Honest impact note:** no *card* currently reads the power of a Legend sitting in the Legends area
— `westbrook-netrunner`'s `protect_legends_lt_power` (`steps.py` 272) compares a Legend that is on
the field stealing, and the web client computes `power_now` only for `s.units(p)` (`web/view.py`
229). So today the deviation is observable through `ops.power()` and nothing else. It is still a
condition the printed text does not contain, in a script whose other clauses are all faithful, and
it starts mattering the moment any card asks what a face-up Legend's power is.

**Rulings checked:** 016 (Gear cannot be re-equipped; Gear on a Legend that Go Solos moves with it —
consistent with the bonus following Royce onto the field), 030 (⊡ on Gear — *Uncertain*, untouched:
Royce has no activated ability), 031 (face-down Legends inactive — `_rebuild_active` filters on
`i_faceup`, so the hook is reached only for a face-up Royce), 034 (a Legend leaving is removed from
the game — untouched). None licenses a zone restriction.

## Unproven

- **U-UNREACHABLE — `meredith-stout-stone-cold-corpo`, "adjusts or swaps **1 or more** friendly
  Gigs".** The script triggers on `gig_changed` (wnc.py 855-858), and `ops.adjust_gig` / `set_gig`
  dispatch that event once **per die**, so an effect moving two friendly Gigs would offer Meredith's
  trash-return twice, where "1 or more" reads like one trigger for the whole effect. I grepped every
  card text in `data/cards/wnc.json` for adjust/increase/decrease/swap: all sixteen are "a Gig" or
  "a friendly Gig with a rival Gig" — single-die effects (`afterparty-at-lizzies`,
  `industrial-assembly`, `trust-no-one`, `la-llorona-ghost-of-the-past`,
  `hanako-arasaka-daughter-of-the-emperor`, `maxtac-av`, `6th-street-recruits`, ...), and
  `swap_gigs` likewise dispatches exactly one event. No legal game reaches a two-Gig rival adjust,
  so the difference cannot be shown and is not a finding.
- **S-SUSPICION — `zetatech-berserk`, "for each friendly face-up Legend".** A friendly Legend that
  has gone solo is face-up but on the field, and `c.legends(p, faceup=True)` reads only the Legends
  area, so it is not counted. I judge the script right — ruling 015's default is that a gone-solo
  Legend vacates its Legend slot and "is a Unit now", exactly the trap list's presumed-D case — and
  every discount probe I wrote PASSED: 3 friendly face-up Legends -> 6-3 = 3 €$; 0 friendly face-up
  with 3 **rival** face-up -> 6 €$; the "minimum of 1" clamp is unreachable, since a player has only
  3 Legends against a printed cost of 6.

## Clean

Checked clause by clause against the printed text; the probes behind each line were run:

- **`zetatech-berserk`** — "Play this Gear for -1 €$ for each friendly face-up Legend, to a minimum
  of 1 €$." `self_cost` (wnc.py 812) counts only the controller's face-up Legends and floors at 1;
  rival face-up Legends give nothing (probed 6 €$), three friendly ones give 3 €$;
  `ops.play_cost` applies `self_cost` only when not going solo, right for a Gear.
- **`riot-shield`** — "(Equip to a friendly Unit or face-up Legend.) / BLOCKER / Rivals must pay
  +2 €$ to use GO SOLO." `cost_mod` (831) adds +2 only when `go_solo and p != c.player`: probed that
  the controller's own GO SOLO is untaxed while the *rival's* Riot Shield adds exactly 2 (V, 5 €$ ->
  7 €$), that the tax gates legality (5 Eddies -> no GoSolo offered; 7 Eddies -> offered, all 7
  paid), and that BLOCKER reaches the host through the Gear's printed keyword (`ops.has_keyword`).
  Redirect scope is ruling 011/012 territory and untouched by this card.
- **`saul-bright-stormrider`** — "Other friendly Units have +2 power while attacking. / At the end
  of your turn, ready up to 3 friendly Units." `pm` (838-840) requires ATTACKING, `unit != c.inst`
  ("Other"), friendly ownership and FIELD; `ev` (842-845) fires on its controller's `end_turn` and
  asks `choose_many(..., 0, 3)` — probed with four spent friendly Units and one spent rival Unit:
  15 options (C(4,0..3)), at most three picks, the rival Unit never a candidate. "Up to" is the
  `lo=0` branch; narrowing candidates to spent Units only removes no-op picks.
- **`meredith-stout-stone-cold-corpo`** — "BLOCKER / +2 power while fighting a Legend / When a Rival
  adjusts or swaps 1 or more friendly Gigs, you may add a card from your trash to your hand."
  `power_mod` (859-860) keys on `unit == c.inst and FIGHTING and VS_LEGEND` (7 vs a Legend, 5 vs a
  Unit); `ev` (855-858) requires actor == rival **and** owner == self, and is `optional=True` ("you
  may"), reading the controller's own trash. Probed: no trigger when the rival *steals* a Gig
  (`ops.steal_gig` emits `steal`, never `gig_changed`), none when the rival adjusts their own die,
  none when the controller adjusts their own die, and declining adds nothing. (Its +2-vs-Legend
  clause is what shows the engine still treats a gone-solo card as a Legend by type — see the
  competing reading under AUD-saburo-arasaka-stubborn-patriarch-1.)
- **`adam-smasher-ender-of-legends`** — "GO SOLO / PLAY: Defeat a rival Unit." `on_play` (866) is
  mandatory (`defeat_one` with no `optional`): with two rival Units the prompt has exactly two
  options and no decline; with none it does nothing. Probed that **Calling** Adam Smasher face-up
  does not fire PLAY (only `engine.go_solo` and `play_card` push `Trigger.PLAY`) — ruling 032:
  "Does a Legend's PLAY trigger when it GOES SOLO? **Yes** ... Calling a Legend is not playing it."
- **`johnny-silverhand-never-stop-fighting`** — "The first time this Unit wins a fight each turn,
  ready it. / This Unit wins all fights against CORPO Units." `ev` (877-879) uses `c.once("won")` —
  probed: readied after the first win, still spent after a second win the same turn (ruling 019,
  *Uncertain*: it fixes the reset point, and `EndTurnCleanupStep` clears the counters exactly as the
  default says). `extra={"wins_vs_tag": "CORPO"}` is applied symmetrically by `steps.fight`, so
  Johnny also wins as the defender — probed with a 14-power CORPO attacker (Meredith + 3 Gorilla
  Arms), which died to Johnny's 8 while Johnny readied. Against a CORPO **Legend** that has gone
  solo the engine gives Johnny the win, the same "a gone-solo Legend is a Unit" reading argued for
  in AUD-saburo-arasaka-stubborn-patriarch-1.
- **`modded-kusanagi`** — "ADRENALINE / At the end of your turn, return this Unit to its owner's
  hand." `ev` (883-886) fires only on its controller's `end_turn` and only while `c.in_play()`;
  probed that it stays on the field through the *rival's* end of turn, and that equipped Gear
  travels with it to hand (`docs/rules.md`: "When the host card moves to a different area, all
  equipped Gear goes with it"). ADRENALINE is data-only.
- **`modded-muramasa`** — "At the end of your turn, if you have less ★ (Street Cred) than a Rival,
  ready this Unit." `ev` (891-893) fires on its controller's `end_turn` under `c.less_cred()`
  (`street_cred` = sum of that player's die faces). Probed: readied when behind (4 vs 5), left spent
  when ahead and when tied. Ruling 038 (Null Street Cred with no Gigs, "smaller than 0 when
  compared") changes no outcome here: a Gig area holding dice always sums to >= 1, so the plain `<`
  and the Null rule agree on every reachable pair.
