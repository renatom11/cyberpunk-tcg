## Findings

### AUD-6th-street-recruits-1 — 6th Street Recruits — class B4 (scope error: a<->all / who counts as a Unit)

**Printed text** (`data/cards/wnc.json`, `6th-street-recruits`):
> "When a friendly Unit steals a d6, increase a Gig by up to 6."

**The clause at fault:** the trigger condition "a friendly **Unit**".

#### Leg B — clause map

`src/cptcg/cards/sets/wnc.py:939-949`

```python
@script("6th-street-recruits")
def _():
    def ev(c, e):
        if e[0] == "steal" and e[3] == 6 and c.s.i_owner[e[1]] == c.player \
                and c.d(e[1]).type is UNIT:
            c.adjust_up_to([c.player, c.rival], 1, 6, prompt="Increase a Gig")
    return CardScript(on_event=ev, events=frozenset({"steal"}))
```

| # | Clause | Implementation | Verdict |
|---|--------|----------------|---------|
| 1 | "When ... steals" | `e[0] == "steal"`; the event is dispatched from `do_steal` (`core/steps.py:312`) as `("steal", unit, thief, sides, value)` | correct |
| 2 | "a d6" | `e[3] == 6` — `e[3]` is the die's *sides*, so exactly a six-sided die | correct |
| 3 | "a friendly ..." | `c.s.i_owner[e[1]] == c.player` | correct |
| 4 | "... **Unit**" | `c.d(e[1]).type is UNIT` — the **card type** printed in the top right | **wrong: excludes a GO SOLO Legend, which is a Unit while on the field** |
| 5 | "increase a Gig" | `c.adjust_up_to([c.player, c.rival], ...)` — either player's Gig | correct (see Unproven N-NOTE) |
| 6 | "by up to 6" | `lo=1, hi=6`, `optional=True` in `EffectCtx.adjust_up_to` (`core/effects.py:355-375`), which also drops amounts that would take the die off-face | correct |

Why clause 4 is wrong:

- **GO SOLO keyword text** — `docs/rules.md:90`, and *printed in full on a card in this very set*
  (`v-corporate-exile`: "GO SOLO (Pay this Legend's cost to **play it as a ready Unit**. …)").
  Card text is authority #1, and it says the thing on the field is a Unit.
- **Ruling 015** (`docs/rulings.md`): "A `GO SOLO` Legend on the field — still spendable as an
  Eddie? … **Not spendable** (*it is a Unit now*) …". The ruling's own default reasoning is that a
  solo'd Legend *is* a Unit.
- **The engine already agrees.** `GameState.units()` (`core/state.py:201-205`) returns every
  non-Gear, unhosted card in `Zone.FIELD`, which includes a GO SOLO Legend; the test below asserts
  `goro in s.units(0)` and that assertion passes. So sibling cards in this batch that use
  `c.units()` (Wraith Marauders) or `c.rival_units()` *do* treat a solo'd Legend as a Unit, while
  6th Street Recruits does not. The deviation is internal to the set file, not a house convention.

This is **not** covered by the "GO SOLO slot vacation" trap: no slot behaviour is involved, and the
script is shown to deviate from ruling 015's *stated default*, not from an alternative reading.

Counter-reading considered and rejected: `rogue-amendiares-preem-solo` reads "When a friendly
**Legend** steals a Gig" and is scripted as `c.d(e[1]).type is LEGEND` (`wnc.py:1377`), which proves
a solo'd Legend is still a Legend. That is compatible — a GO SOLO Legend is a Legend *card* played
as a Unit, so both triggers should fire. It does not license excluding it from "a friendly Unit".

**Rulings checked:** 015 (applies — quoted above), 032 ("GO SOLO reads … *play it* as a ready
Unit"; applies as corroboration), 033 (which Legends can be played to the field — Goro Takemura
qualifies), 027 (GO SOLO enters lagged but may still attack — makes the scenario legal), 037
(off-face adjustment — clause 6 honours it), 009 (an empty Gig area is not a legal attack target —
scenario avoids it).

### AUD-maelstrom-zealots-1 — Maelstrom Zealots — class B2 (missing clause: the tie case)

**Printed text** (`data/cards/wnc.json`, `maelstrom-zealots`):
> "When this Unit loses a fight, defeat the opposing rival Unit. (Units with power 0 don't steal Gigs.)"

**The clause at fault:** the trigger condition "When this Unit **loses a fight**" — a tied fight is
a fight this Unit lost, and the card never fires on one.

#### Leg B — clause map

`src/cptcg/cards/sets/wnc.py:960-966`

```python
@script("maelstrom-zealots")
def _():
    def ev(c, e):
        if e[0] == "fight_lost" and e[1] == c.inst:
            c.defeat(e[2])
    return CardScript(on_event=ev, events=frozenset({"fight_lost"}))
```

| # | Clause | Implementation | Verdict |
|---|--------|----------------|---------|
| 1 | "When this Unit loses a fight" — decisive loss | `e[0] == "fight_lost" and e[1] == c.inst`; `core/steps.py:385,388` dispatches `("fight_lost", loser, winner)` inside `if a_wins: … elif t_wins: …` | correct (control test passes) |
| 2 | "When this Unit loses a fight" — **tie** | nothing. `fight()` computes `a_wins, t_wins = pa > pt, pt > pa`; on a tie both are False and **neither `fight_won` nor `fight_lost` is dispatched at all** (`core/steps.py:377-390`) | **unimplemented** |
| 3 | "defeat the opposing rival Unit" | `c.defeat(e[2])` — `e[2]` is the other combatant, always the rival's card (`fight(a, t)` is only ever called across sides) | correct |
| 4 | not gated by `zero_power_cannot_defeat` | `c.defeat` → `ops.defeat`; the CR 9.19.2 clamp lives only inside `fight()`'s own defeat bookkeeping, so this 0-power Unit's *triggered* defeat still lands | correct, and matches the card's whole design |
| 5 | "(Units with power 0 don't steal Gigs.)" — reminder text | `ops.steal_count` (`core/ops.py:427-429`) returns 0 at power ≤ 0, and `ResolveAttackStep` returns when `n <= 0` | correct (engine-level, nothing for the script to do) |

Why clause 2 is a real gap:

- **Ruling 010** (Settled, CR 9.17–9.19): "Do 0-power Units fight? **Yes**, and they lose every
  fight they don't tie — but **a 0-power Unit cannot defeat a Unit** as the result of a fight
  (CR 9.19.2). **Ties: both lose and both are defeated** (CR 9.17.3)." The sentence about ties says
  *both lose*, which is exactly the trigger condition on this card.
- **`docs/rules.md:137-138`**: "Compare both Units' power. The higher power Unit defeats the other;
  **on a tie they defeat each other**." If the opposing Unit defeated Zealots, Zealots lost the
  fight.
- The gap is observable precisely where it matters. Zealots is power 0, so the ties it can reach
  are 0-vs-0 ties, and ruling 010's *other* half (`zero_power_cannot_defeat`) stops the tie itself
  from defeating either Unit. So a tied fight today leaves both Units standing and Zealots' printed
  effect silently does nothing; under the printed text the opposing rival Unit should be defeated.
  (At a non-zero tie both Units die from the fight anyway, so this is the case that shows it.)

Ruling 010 is **Settled with a CR citation** and is not on the presumed-D trap list. Note the fix
lives in `core/steps.fight()` (dispatch `fight_lost` for both sides on a tie), not in the card
script — but the audited clause is the card's, and it is not implemented.

**Both readings, for honesty** (this is the one place in the batch where I would accept an
argument): ruling 010's first sentence, "they lose every fight **they don't tie**", can be read as
holding "tie" apart from "lose". Against that: it is a remark about 0-power Units not *winning*,
and the same row then states outright that in a tie "both lose", with `rules.md` independently
saying the tied Units "defeat each other". I judge the printed-text reading (a tie is a loss for
both) to be the correct one and filed accordingly; a reviewer who takes the other reading should
reclassify this as **D — ruling 010, first sentence** and delete the test.

**Rulings checked:** 010 (applies — quoted above), 029 (power floors at 0, so 0-vs-0 is the
reachable tie), 024 (an attacker is spent, so the target legality of a spent rival Unit holds),
034 (a defeated Legend is removed, not trashed — avoided by using a Unit as the opposing card),
009 (empty Gig area not attackable — scenario gives the rival a die so the attack menu is normal).

## Unproven

- **S-SUSPICION — `maxtac-squadron`: "ready a friendly face-up Legend" and a GO SOLO Legend on the
  field.** Symmetric to AUD-6th-street-recruits-1: `c.legends(faceup=True)` reads only the Legends
  *area* (`state.legends`, `core/state.py:214`), so a face-up Legend that GO SOLO'd onto the field
  and is sitting spent cannot be readied. I built and ran that board (MaxTac spent, Goro Takemura
  solo'd and spent by attacking, end of turn): Goro stays spent. **I am not filing it.** "Face-up"
  is a Legends-area orientation — a solo'd Legend is on the field as a Unit, and ruling 015's
  default reading of it ("it is a Unit now") cuts *against* calling it a "face-up Legend" there.
  Both halves of the batch's GO SOLO question cannot be answered the same way from the same
  evidence, and here the evidence points at the script being right. Recorded so the next auditor
  does not re-derive it.
- **N-NOTE — `6th-street-recruits` / `la-llorona-ghost-of-the-past`: "increase a Gig" is offered
  over *both* players' Gig areas** (`c.adjust_up_to([c.player, c.rival], …)`). The in-file comment
  at `wnc.py:941-944` defends this, and the card data corroborates it rather than contradicting it:
  `jackie-welles-pour-one-out-for-me` is the only card in the set that narrows the scope
  ("decrease a **friendly** Gig"), and `meredith-stout-stone-cold-corpo` reads "When a **Rival**
  adjusts or swaps 1 or more friendly Gigs, …", which only makes sense if an unscoped "a Gig" can
  reach across the table. The offer is also always optional, so no forced self-harm. Style note
  only; no finding.

## Clean

Each of these was walked clause by clause in both directions (text→script and script→text), and
each behaviour below was confirmed by running the board, not by reading alone.

- **`maxtac-squadron`** — "At the end of your turn, if this Unit is spent, ready a friendly face-up
  Legend." `end_turn` + `e[1] == c.player` (your turn only), `c.s.i_spent[c.inst]` (the condition),
  mandatory `choose` over `c.legends(faceup=True)` filtered to spent ones. Verified: a face-down
  spent Legend is not offered; two face-up spent Legends give a 2-option choice with **no** decline
  option (mandatory, as printed); a ready MaxTac triggers nothing. Filtering to spent Legends is a
  no-op narrowing (readying a ready card does nothing). See S-SUSPICION above for the solo'd-Legend
  edge.
- **`delamain-cab`** — "At the end of your turn, if this Unit stole a Gig this turn, ready 1 Eddie."
  `("stole", c.inst) in c.s.used`, written by `do_steal` (`steps.py:311`) and cleared in
  `EndTurnCleanupStep` (`steps.py:181`) — i.e. *after* the `end_turn` dispatch at `steps.py:169`, so
  "this turn" is exact. Verified: attacking a Unit (a fight, no steal) readies nothing; a steal
  readies one Eddie. `ready_eddies` touches the Eddies area only, matching "1 Eddie" rather than
  "1 card". A steal prevented by a replacement effect never reaches `do_steal`, so it correctly does
  not count.
- **`v-roamer-of-the-badlands`** — clause 1 "When this Unit steals a Gig, increase it by up to 5":
  `idx = len(c.gigs()) - 1` is the die just appended by `ops.steal_gig` (`ops.py:479`), amounts
  restricted to 1..5 and to the die's faces, `optional=True` for the "up to". I stress-tested the
  index against two steals in one attack (V + Gorilla Arms vs a d6 and a d8): each steal raises its
  own die (`[(4,2)] → [(4,2),(6,4)] → [(4,2),(6,4),(8,6)]`), because steals only ever *append* and
  each question is answered before the next steal step runs. Clause 2 "At the end of your turn, if
  you control 2 or more Gigs with 8+ value, draw 1": `gigs_8plus(c) >= 2` over your own area;
  verified that one 8+ die draws nothing and two do.
- **`wraith-marauders`** — "When this Unit steals a Gig, ready another friendly Unit with power
  equal to the Gig's value." `v = e[4]` is the stolen die's value; candidates are `c.units()`
  (friendly, and includes a solo'd Legend, consistent with ruling 015), `u != c.inst` ("another"),
  `c.power(u) == v` (exact equality, current power). Verified Wraith itself is never a candidate
  even when its own power matches the value, and that a non-matching spent Unit is not offered.
  Mandatory, as printed.
- **`maelstrom-goons`** — "When this Unit steals a Gig, if it's equipped, a Rival discards 1."
  `e[1] == c.inst` (this Unit), `c.equipped(c.inst)` ("it" = this Unit, checked at trigger time),
  `discard_rival(c, 1)` → `c.discard(1, player=c.rival)`, so the *Rival* chooses their own discard.
  Verified: unequipped Goons steal without any discard; equipped Goons empty a 1-card rival hand.
- **`la-llorona-ghost-of-the-past`** — "BLOCKER / When this Unit uses BLOCKER, increase a Gig by up
  to 3." BLOCKER is a data keyword, handled by the engine. The trigger listens to
  `("blocked", blocker, attacker)` dispatched from `_reaction` (`engine.py:256`), which is the only
  place a Block is taken, so "uses BLOCKER" is exact. Amounts 1..3, positive only ("increase"), with
  the decline that "up to" requires. Rulings 012/014 (Uncertain / lagged blockers) are engine-side
  and untouched by this script. See the N-NOTE for the cross-table Gig scope.
- **`augmented-negotiators`** — "BLOCKER. / When this Unit uses BLOCKER, a Rival discards 1." Same
  `blocked` hook as above, `discard_rival(c, 1)`. Verified on the rival's turn: the attacker's hand
  loses its card and the discarder is the Rival.
- **`rita-wheeler-no-stupid-questions`** — "BLOCKER / The first time this Unit is spent each turn,
  draw 1, then discard 1." `("spent", inst)` is dispatched by `ops.spend` (`ops.py:325`) only for
  cards in FIELD/LEGENDS, `c.once("spent")` keys `(inst, "spent")` into `s.used`, cleared every
  turn in `EndTurnCleanupStep` — ruling 019's `once_per_turn_scope = "turn"` default, which the
  trap list presumes D, and the card says "each turn", so it matches. Order is right: `c.draw(1)`
  resolves immediately and `c.discard(1)` queues the question, so the freshly drawn card is a legal
  discard ("draw 1, **then** discard 1"). Verified: readying and re-spending Rita in the same turn
  loots nothing the second time; blocking on the rival's turn does loot (a block is a spend).
- **`alt-cunningham-mother-of-daemons`** — clause 1 "When a friendly equipped Unit or Legend is
  spent, draw 1": `c.s.i_owner[e[1]] == c.player and c.equipped(e[1])`; the "Unit or Legend" half
  needs no test because `ops.spend` never dispatches `spent` for Gear or for anything outside
  FIELD/LEGENDS. Verified: a friendly equipped face-up Legend spent in the Legends area draws;
  a *rival* equipped Unit being spent draws nothing. Clause 2 "When a rival Unit would steal a Gig,
  you may discard 1 with cost equal to that Gig's value. If you do, the Gig isn't stolen": a
  `would_steal` replacement hook, run by `StealOneStep` before `do_steal` with the victim's own
  hooks first; `victim != c.player → False` scopes it to your own Gigs; candidates are exactly
  `cost == that die's value`; `optional=True` is the "may", and the decline branch calls `do_steal`
  so the Gig *is* stolen when you pass. Verified it is offered to Alt's controller, that it fires
  once per die (a two-die attack asks twice), and that the accepted branch leaves the die in place.
  Ruling 037 is not engaged (no adjustment); ruling 005 (stolen dice are not rerolled) means the
  value read for the cost match is stable.
