**Every declared kind in this batch is the right kind.** No `events=` frozenset in the set is
narrower than what the printed words name; no hook fires on a kind its text does not mention. The
two findings below are both about the *guard inside* the hook, not about the filter.

## 2. The majority pattern, and the two departures

### The pattern: "Unit" includes a GO SOLO Legend on the field

The pool has settled this three times, in three different event kinds, and each time the fix was to
*stop* excluding the solo'd Legend:

* `steal` — AUD-6th-street-recruits-1 (batch a11): gates on `CardDef.type is UNIT`, so a d6 stolen
  by a solo'd Legend never fires "When a friendly Unit steals a d6".
* `fight_won` — AUD-satori-sword-of-saburo-1 (batch a12): same gate, same consequence.
* `defeated` — AUD-river-ward-detective-on-the-hunt-1 (batch a13): same gate, same consequence.

The rule behind all three is printed on `v-corporate-exile` itself — GO SOLO reads "Pay this
Legend's cost to **play it as a ready Unit**" — and is settled twice in `docs/rulings.md`:
ruling 032 ("Does a Legend's PLAY trigger when it GOES SOLO? **Yes** — GO SOLO reads 'pay this
Legend's cost to *play it* as a ready Unit'") and ruling 015 ("**Not spendable** (it is a Unit
now)"). The engine agrees in code: `engine.go_solo` calls `push_trigger(Trigger.PLAY, ...)` *and*
`dispatch(s, ("played", inst, p))`, and `s.units(p)` lists the solo'd Legend.

**F1 is the fourth event kind, `played`, and the one nobody was assigned.** `steal`, `fight_won`
and `defeated` were each caught by the agent who happened to hold that card; `played` has exactly
three hooks in the whole set and only one of them names a Unit:

| hook | printed noun | type gate | can a GO SOLO Legend hit it? |
|---|---|---|---|
| `judy-alvarez-braindance-maestro` | "a BRAINDANCE **Program**" | `type is PROGRAM` | no — Programs never go solo |
| `viktor-vektor-drop-your-illusions` | "your first CYBERWARE **Gear**" | `type is GEAR` | no — Gear never goes solo |
| `jackie-welles-pour-one-out-for-me` | "a Blue **Unit** or Blue Gear" | `type in (UNIT, GEAR)` | **yes, and it is excluded** |

That is the cross-cutting sentence: Jackie is the only `played` hook in the set whose printed noun
is "Unit", `go_solo` is the only code path that dispatches `played` for a card whose `CardDef.type`
is `LEGEND`, and those two facts meet on exactly one card. A reader looking at Jackie's neighbours
(two Legends whose nouns are Program and Gear) has nothing to compare against.

### F1 — AUD-jackie-welles-pour-one-out-for-me-1

> "The first time you play a Blue Unit or Blue Gear each turn, you may decrease a friendly Gig by
> up to 2. If it becomes a min Gig, draw 1."

```python
if e[0] == "played" and e[2] == c.player and c.d(e[1]).color.name == "BLUE" \
        and c.d(e[1]).type in (UNIT, GEAR) and c.once("blue"):
```

Playing `v-corporate-exile` — a Blue Legend with GO SOLO, whose own reminder text says you play it
as a Unit — dispatches `("played", inst, 0)`, and Jackie declines it because `CardDef.type` is
`LEGEND`. Verified: with Jackie face-up and a d6 showing 3, `GoSolo(v-corporate-exile)` leaves the
main menu untouched, while playing `psycho-squad` (a Blue Unit) from hand offers
`[(0,), (1,), ()]` — decrease by 2, decrease by 1, decline.

The set contains two Blue Legends with GO SOLO (`v-corporate-exile`, `sasha-yakovleva-wont-let-you-down`),
so this is a live line in a Blue deck, not a corner case. The once-per-turn guard is correctly
placed *after* the colour/type test, so it is consumed only by a qualifying play — fixing the type
test does not disturb it.

Test: `test_jackie_fires_when_a_blue_legend_goes_solo`, with the Blue-Unit control beside it.

### F2 — AUD-rogue-amendiares-queen-of-the-afterlife-1

> "The first time another friendly Unit steals a Gig with value less than its power each turn,
> ready 2 Eddies."

```python
if e[0] == "steal" and e[1] != c.inst and c.s.i_owner[e[1]] == c.player \
        and e[4] < c.power(e[1]) and c.once("ready_eddies"):
```

`c.power(inst)` defaults to `sit=0`, i.e. power read *out of* any situation. But the comparison is
made at the instant of a steal, and a steal only ever happens while the thief is attacking — so
"its power" is the attacking power, and the engine itself says so twice on the way here:

* `ops.steal_count(power(s, a, ATTACKING))` decides *how many* Gigs the Unit takes;
* `steps.stealable` decides *which* Gigs it may take, and the one printed rule in this set that
  compares a Gig's value against a thief Unit's power — Chrome Fang's "rival Units can't steal
  friendly Gigs with value higher than **their power**" — is applied there, with `ATTACKING`.

Rogue prints the same comparison in the opposite direction and reads a different number for it.
Verified: with `saul-bright-stormrider` in play ("Other friendly Units have +2 power while
attacking"), a base-4 `emergency-atlus` attacks and steals a d6 showing 5. Its power at that moment
is 6 — the number the engine used to let it steal at all — and 5 < 6, so Rogue should ready 2
Eddies. She readies none, because 5 is not less than 4. Remove Saul and the same board pays out
(control), so the board is sound and the difference is exactly the situational read.

`wraith-marauders` reads `c.power(u)` with `sit=0` too, but there the subject is a *different*,
non-attacking Unit ("ready another friendly Unit with power equal to the Gig's value"), so `sit=0`
is right on that card. Rogue is the only place in the set where "its power" refers to the thief,
mid-steal, and is read without `ATTACKING`.

## 3. Cards checked and found correct

Each of these was suspected, given a board, and behaved as printed. The passing scenarios are in
`tests/cards/audit/test_confirmed_b01.py` — coverage the pool did not have.

* **goro-takemura-vengeful-bodyguard** — "When a friendly Unit uses BLOCKER". The only `blocked`
  hook in the set that names *a friendly Unit* rather than *this Unit* (la-llorona and
  augmented-negotiators both use `e[1] == c.inst`). It gates on owner and **not** on
  `CardDef.type`, which is the *opposite* of the F1 mistake and is right: a GO SOLO
  `goro-takemura-hands-unclean` on the field has BLOCKER, is listed by `s.units()`, is the only
  thing `legal.py` will ever offer a `Block` for, and does fire the discard-to-draw offer.
  Confirmed for both a solo'd Legend and a plain BLOCKER Unit.
* **alt-cunningham-mother-of-daemons** — "When a friendly equipped Unit or Legend is spent".
  `ops.spend` dispatches `spent` only for FIELD/LEGENDS non-Gear, so the hook's bare owner+equipped
  test cannot pick up a spent Eddie or a spent Gear. Confirmed: paying for a Gear with an equipped
  face-up Legend as the only payable source draws 1.
* **netwatch-netdriver** / **tetratronic-rippler** / **arasaka-emergency-radioport** — all three use
  the shared `_host_spent` helper, so the "this Unit **or Legend**" half is real: confirmed that a
  Legend host spent for payment fires the draw. Radioport additionally offers the free Call only
  when the looked-at face-down Legend is ARASAKA or has GO SOLO; a plain Legend is looked at (the
  chooser learns it) and nothing else happens, which is exactly the printed conditional.
* **delamain-cab** — "if this Unit stole a Gig this turn" reads `("stole", inst)`, which
  `steps.do_steal` records for the thief instance, and `s.used` is cleared in `EndTurnCleanupStep`
  *below* the `end_turn` dispatch, so the marker is still there when the hook runs. Confirmed both
  ways: a steal readies 1 Eddie, no steal readies none.
* **panam-palmer-nomad-cavalry** — "if 5 or more friendly Units and/or Legends are equipped, ready
  them". `s.units()` excludes attached Gear and a solo'd Legend is in `units()` and not in
  `legends()`, so the count cannot double. Confirmed with 4 equipped Units plus the equipped Panam.
* **hanako-arasaka-daughter-of-the-emperor** — `start_turn`, `c.value_pairs()` counts each die in at
  most one pair. Confirmed: two pairs draw 2 extra cards, four distinct values draw none.
* **adrenaline-converter** — the one card in the batch with **no** `on_event` at all; the condition
  is re-read on every `has_keyword` call via `kw_mod`, which is right because a steal changes the
  Gig counts mid-turn. It grants to `c.host()` without checking the host is a Unit, which is the
  shape filed as AUD-dying-night-vs-pistol-1 on the Gear next to it — but ADRENALINE only ever
  matters in `legal.can_attack`, and a face-up Legend in the Legends area cannot attack, so the
  extra grant is inert and there is nothing a printed-text test could assert. Not filed.
* **kerry-eurodyne-axe-attitude-audience** — checked the reroll bookkeeping specifically, since
  "reroll it **once**" sounds per-Gig while `(inst, "reroll_offer")` is a per-turn key. They are the
  same thing here: `gain_gig` is the only caller that dispatches `gig_rolled` and it runs once a
  turn from `TakeGigStep`. `reroll_gig` and `steal_gig` do not dispatch it, and ruling 005 (Settled)
  says stolen dice are not rerolled, so there is no second roll for the min/max clause to miss.
  The existing AUD-kerry-eurodyne-axe-attitude-audience-1 covers the separate ignore-the-result
  question. Nothing further filed.
* **pepe-najarro-working-doubles** — "ready up to 2 MERC Legends in your Legends area" is
  `choose_many(..., 0, 2, ...)`, and "up to 2" genuinely permits zero. It does **not** filter on
  face-up, and it should not: the one card in the set that means face-up says so
  (`maxtac-squadron`, "ready a friendly face-up Legend") and does filter. The set is consistent.
* **caliber-totentanzs-top-dog** — "If **the card's** cost equals the value of a friendly Gig" is a
  back-reference to the card just discarded, so hanging it off the discard continuation is correct
  (and is the exclusion `_BACKREF` in `test_script_lints.py` exists to protect). `defeat_one`
  defaults to `optional=False`, so the unconditional PLAY defeat stays mandatory.
* **evelyn-parker-scheming-siren**, **placide-voodoo-sentinel**, **dying-night-vs-pistol**,
  **zetatech-faceplate**, **gorilla-arms**, **maelstrom-zealots** — no new `on_event` issue.
  The open findings on the last four (AUD-dying-night-vs-pistol-1, AUD-tail-clause /
  zetatech-faceplate, AUD-gorilla-arms-1, AUD-maelstrom-zealots-1) are not re-filed here.

## 4. Things deliberately not filed

* **Once-per-turn guards.** Every "the first time … each turn" hook in the batch has a `c.once(...)`
  and every one places it last in the condition, so it is consumed only by a qualifying event:
  gorilla-arms `once("steal")`, jackie `once("blue")`, rogue `once("ready_eddies")`. The set-wide
  sweep found no missing guard; the one genuine per-event/per-action mismatch,
  `evelyn-parker-beautiful-enigma` readying an Eddie per die instead of per steal of "1 or more
  Gigs", is already AUD-evelyn-parker-beautiful-enigma-1 (batch a13) and is not my card.
* **`s.used` clearing at every turn boundary** (so `once()` is per game-turn, not per player-turn)
  is ruling 019, settled on purpose.
* **`goro-takemura-vengeful-bodyguard`'s BLOCKER redirect scope** is ruling 012.
* **Off-batch observation, not filed because the card is not mine:**
  `yorinobu-arasaka-steel-dragon`'s `defeated` hook is the only hook in the set whose printed noun
  carries no side ("an ARASAKA Unit is defeated") while the code restricts it to `e[2] == c.player`.
  That is already AUD-yorinobu-arasaka-steel-dragon-1 (batch a06); recording it here only because
  the cross-cutting read confirms it is the single side-scoping outlier among all 39 hooks — every
  other hook whose text says "friendly" checks owner, and no other hook adds an owner check the
  text did not ask for.
